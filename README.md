# REDZONE — pure touchdown experience (Meta Quest, Entertainment track)

A cinematic redzone moment for VR. You start as a viewer — broadcast desk,
commentary, the play diagrammed in color — then a wipe transition drops you
*into* it: stadium swallows the screen, ball in your hand, crowd deafening.
The hands-first throw is the whole interaction.

- **Blue moments**: a run (RB) is the probable play — a broadcast-style
  cinematic. The handoff happens on the snap; the run is destiny.
- **Red moments**: passing — the probable play is YOUR throw, first-person.
  Snap, read, throw the touchdown.
- **No game systems**: no playbook, no downs, no score. A failed moment just
  restages — "run it back."
- **Procedural field**: regulation 120×53.3-yard field (arcade-scaled), yard lines, end zones,
  goalposts — zero binary assets, builds at runtime.

## Requirements (your machine)

- **Unity 6000.3.25f1** via Unity Hub, with **Android Build Support** (SDK + NDK) installed
- **Meta XR All-in-One SDK v81+ (v207)** from the Unity Asset Store (recommended), *or* plain
  XR Interaction Toolkit (the gameplay code only depends on XRI, so both paths work)
- A Meta Quest 2/3/3S for device builds; Quest Link works for in-editor testing

## Setup

1. Copy this `unity/` folder to your machine and open it in Unity Hub (Unity 6000.3.x).
   Package Manager will resolve `Packages/manifest.json` automatically (Input System,
   XR Management, XR Interaction Toolkit).
2. Import the **Meta XR All-in-One SDK** from the Asset Store (or skip if going XRI-only).
3. In Unity: **NFLSim → Build Experience Scene**. This creates
   `Assets/_NFLSim/Scenes/RedzoneExperience.unity` with the field, players, ball, and
   broadcast rig wired.
4. Add your camera rig to the scene:
   - Meta path: drag `OVRCameraRig` prefab into the scene, **disable** the `PreviewCamera`
     (it exists so you can test on desktop without a headset).
   - XRI path: `GameObject → XR → XR Origin (VR)`, then disable `PreviewCamera`.
   - Position the rig's origin at the glowing **QB spot** marker (5 yards behind the line).
5. XR Plug-in Management: **Edit → Project Settings → XR Plug-in Management → Android tab →
   check Oculus**. (The `NFLSim → Apply Quest Build Settings` menu handles the rest:
   IL2CPP, ARM64, min SDK 32, bundle id `com.marley.nflsim`.)
6. Press Play (Link) or **Build and Run** to the Quest.

## Controls

| Input | Action |
|---|---|
| A button / Space (desktop) | Take the field (from broadcast) → snap the ball |
| Grab ball (grip/trigger) + throw motion, release | Throw — speed & direction from your hand |
| Physically walk | Move in the pocket (no artificial locomotion) |

## Tuning

Everything lives in `Assets/_NFLSim/Scripts/Core/SimConfig.cs`:
world scale (`UnitsPerYard = 0.6`, i.e. a 40-yard throw ≈ 24 m), player speeds,
catch/tackle/sack radii, throw boost, scenario colors (`ScenarioBlue` /
`ScenarioRed`), wipe/celebration/retry pacing. Team colors are on `FieldBuilder`
(defaults: black & gold).

## Known limitations

- No audio yet — crowd/commentary is the P1 atmosphere pass (see PROJECT_PLAN.md).
- No artificial locomotion; no haptics yet.
- Defense is man-coverage only; receivers don't adjust routes.
- 4 scripted scenarios; the set grows by appending to `ScenarioSet.cs`.
